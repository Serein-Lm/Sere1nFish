# 数字人全双工语音与远端 OBS 接入

## 1. 百炼全双工语音

系统使用 `qwen-audio-3.0-realtime-plus`。浏览器只连接 Sere1nFish 的鉴权 WebSocket，后端再代理到百炼 Workspace；百炼 API Key 不会下发到浏览器。

该模型是实时语音对话模型：它听取麦克风输入，再使用系统音色或复刻音色生成 AI 回答。它不是逐字保留原话的实时 Voice Conversion 模型，不能把本人每句话无延迟地直接转换成另一种声线。

### 管理员配置

在“配置管理 -> 百炼实时语音”中维护 `cosyvoice` 配置段。最小配置如下：

```json
{
  "api_key": "<百炼 API Key>",
  "workspace_id": "<Workspace ID>",
  "region": "beijing",
  "realtime_model": "qwen-audio-3.0-realtime-plus",
  "realtime_voice": "longanqian",
  "realtime_turn_detection": "smart_turn",
  "realtime_max_history_turns": 20
}
```

`api_key` 也可以复用 `bailian.api_key`。敏感字段由配置中心加密保存，不写入 `.env`、日志或 Git。

可选字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `realtime_base_ws` | 根据 Workspace 生成 | 百炼 WSS 地址，后端统一修正为 `/api-ws/v1/realtime` |
| `realtime_instructions` | 空 | 会话默认指令，最多 4000 字符 |
| `realtime_vad_threshold` | `0.5` | `server_vad` 灵敏度，范围 `-1.0` 至 `1.0` |
| `realtime_vad_silence_ms` | `800` | 静音结束判定，范围 200 至 6000ms |
| `realtime_session_timeout_seconds` | `1800` | 单次会话最长时间 |

### 本机使用

1. 使用最新版 Chrome 打开 Sere1nFish HTTPS 页面。
2. 进入“AI 工具箱 -> 语音工具 -> 全双工对话”。
3. 展开“会话与本机设备”，选择 Mac/PC 的麦克风和扬声器。
4. 点击“开始对话”，在 Chrome 和操作系统中允许麦克风权限。
5. 普通环境使用“智能轮次”；外放回声或背景噪声较大时使用“按住说话”。需要语音打断时建议佩戴耳机。

浏览器输入为 16kHz、16-bit、单声道 PCM，百炼输出为 24kHz、16-bit、单声道 PCM。后端不保存原始会话音频或转写，只记录会话状态、耗时和字节数。

### 复刻音色

创建音色时选择“全双工对话”。全双工音色必须以 `qwen-audio-3.0-realtime-plus` 为目标模型创建；TTS 音色不能混用。创建前必须确认已获得声音所有者授权。

## 2. OBS 直连 GPU 换脸

正式链路由 OBS 采集本机摄像头并通过 WHIP 直连公网 GPU。GPU 使用 MediaMTX 接收 WebRTC，FaceFusion 只处理最新帧，再通过 WHEP 返回 H.264 画面。Sere1nFish 仅上传身份图片、创建会话和显示状态，视频不经过业务服务器或前端浏览器。

```text
OBS 摄像头场景 -> WHIP -> GPU/MediaMTX -> FaceFusion -> WHEP -> OBS 浏览器来源 -> OBS Virtual Camera
```

### Sere1nFish 端

1. 进入“AI 工具箱 -> AI 换脸 -> 实时摄像头”，选择“OBS 直连”。
2. 上传一至四张已获授权的身份图片，视频通话优先选择“视频通话”和 `640` 宽度。
3. 确认素材授权，点击“创建 OBS 直连”。
4. 页面会生成 WHIP 地址、Bearer Token 和换脸输出地址。三者都是当前短时会话专用配置，不要转发给其他人。
5. 保持页面打开可查看处理帧、丢弃帧、推理耗时和重连状态；页面本身不采集摄像头。

### OBS 输入与推流

1. 创建“原始摄像头”场景，只添加“视频采集设备”，选择 Mac 的摄像头。
2. 打开“设置 -> 视频”，输出分辨率使用页面建议值；快速档推荐 `640x360`、`15 FPS`。
3. 打开“设置 -> 直播”，服务选择 `WHIP`，填入页面的 WHIP 地址和 Bearer Token。
4. 编码器使用 Apple VT H.264 或其他 H.264 硬件编码器，关键帧间隔设为 `1` 秒，不使用 B 帧。
5. 保持“原始摄像头”作为节目画面，点击“开始直播”。这里是向 GPU 推送摄像头，不是对外直播。

### OBS 换脸输出与虚拟摄像机

1. 创建“换脸输出”场景，添加“浏览器”来源并粘贴页面的换脸输出地址。
2. 宽高使用页面建议值，关闭“场景不可见时关闭源”，避免切换时重新建连。
3. 点击“虚拟摄像机”旁的设置按钮，将输出类型选为“来源”，指定刚创建的换脸浏览器来源。
4. 启动虚拟摄像机，在微信或会议软件中选择 `OBS Virtual Camera`。
5. 不需要开启 OBS 录制。节目画面必须继续保持原始摄像头，不能切到换脸结果，否则会把输出再次推回 GPU 形成反馈回路。

macOS 首次使用摄像头和虚拟摄像机时，在“系统设置 -> 隐私与安全性”授权 OBS；授权后重启 OBS。

### 目标音色

视频与语音使用两条独立实时链路，由 OBS 最终混合。换脸视频直连 GPU；百炼全双工回答仍通过 Sere1nFish 的短时语音浏览器来源进入 OBS。添加语音来源时启用“通过 OBS 控制音频”，本机监听默认关闭，建议佩戴耳机避免回声。

### GPU 安全组

GPU 节点只需开放：

| 端口 | 来源 | 用途 |
| --- | --- | --- |
| `443/tcp` | `0.0.0.0/0` | WHIP/WHEP 信令，以及公网 TLS 证书的自动签发和续期 |
| `8189/udp` | 使用 OBS 的固定公网 IP，无法固定时允许公网 | WebRTC 主媒体通道 |
| `8189/tcp` | 使用 OBS 的固定公网 IP，无法固定时允许公网 | UDP 不可用时的 ICE 回退 |

不要开放 GPU 内部端口 `8443`、`8554`、`8889`、`9997`、`9998`。使用 Caddy 自动证书时，CA 在首次签发和后续续期时都必须能访问 `443/tcp`，因此保持公网放行；业务接口仍受会话 Token 保护。如果必须限制 `443` 来源，应改用自有域名的 DNS-01 证书或自行维护证书续期，不能在自动签发后直接永久收紧。

### 会话安全

- OBS 直连会话默认 15 分钟无活动后过期，关闭会话后凭据立即失效。
- 发布和读取使用不同的高熵 Token；GPU 只保存 SHA-256 摘要，不写数据库、日志或 Git。
- GPU 内部 RTSP 使用独立随机凭据并仅监听 `127.0.0.1`。
- MediaMTX 控制 API、指标和 RTSP 均只绑定回环地址；媒体不录制、不持久化。
- “浏览器测试”保留为兼容诊断模式，仍使用逐帧 JPEG，不应作为正式视频通话链路。

## 3. 快速排查

| 现象 | 检查项 |
| --- | --- |
| 麦克风无法启动 | 页面必须是 HTTPS；检查 Chrome 网站权限和系统麦克风权限 |
| 语音有回声或自己打断自己 | 使用耳机，或切换为“按住说话” |
| 无法选择扬声器 | Chrome/系统不支持输出设备切换时会使用系统默认设备 |
| OBS WHIP 无法连接 | 检查 GPU `443/tcp`、Bearer Token、公网证书和 H.264 编码器 |
| 换脸输出一直等待 | 确认 OBS 已点击“开始直播”，并检查 GPU `8189/udp` 和直连状态 |
| 输出重复套娃 | 节目画面必须保持原始摄像头；虚拟摄像机单独选择换脸来源 |
| OBS 有画面无声音 | 语音是独立浏览器来源；启用“通过 OBS 控制音频”并确认 AI 已回答 |
| 声音重复或触发回声 | 关闭“本地监听”或佩戴耳机，检查 OBS 音频监听未重复输出 |
| OBS 切换场景后断流 | 关闭换脸浏览器来源的“场景不可见时关闭源” |
| 全双工返回 503 | 检查 `cosyvoice.api_key`、Workspace、区域和 WSS 地址 |
