# Target 全局目标库

## 归属与范围

- API 表面：独立只读 `target-library` Router，使用统一项目读取权限。
- 领域读服务：`api.services.target_library` 汇总身份、归属、扫描与历史资料。
- 持久化查询：`api.dao.target_library` 读取已有 Target、项目关系、任务、手机记录和来源版本，并将可重建的身份投影保存到 `targets.library_identity`；不创建第二套来源内容。
- 前端：现有 `/targets` 和独立侧边栏展示全库，类型化 service 调用分页查询，详情使用抽屉。

## 合并与历史语义

1. 默认纳入全部历史 Target 和项目关系，包括历史项目及已停用的项目关联；项目筛选仅用于查找来源。
2. 同一稳定 Target 的跨项目记录归为一个单位。历史重复身份按规范名称、已确认的身份别名/展示名称及直接归属核对后归为同一库条目；不同归属的同名单位及祖先/后代不能自动合并。
3. 合并只建立统一读模型，保留所有原 Target、项目、来源、任务和版本身份。历史资料按来源文档身份去重，原始来源与归档版本始终可以追溯。
4. 控股关系和主管关系保留方向、项目来源及证据。多种直接归属并存时显示各条已存关系，不将间接关系伪装成直接关系。
5. 扫描时间取关联任务实际开始/结束和采集记录时间；没有实际执行证据时标记为待扫描，不能使用名称更新时间充当扫描时间。
6. 手机增量分别展示最近执行、成功时间边界与本轮状态。排队、部分完成、失败不得显示为成功覆盖。
7. 内容变化由已保存的来源版本和扫描结果提供；旧手机记录缺少正文版本时如实保留现有证据，不生成虚构的历史差异。
8. 时间统一按北京时间显示，系统时间精确到秒，原文日期保留真实精度。

## 分析数据字典与计数口径

| 层 | 主键与粒度 | 分析用途 |
| --- | --- | --- |
| `targets` | 一个原始机构身份 / target_id | 规范名称、别名、根域名与身份投影；`library_identity.canonical_target_id` 为全库归并键，旧投影保存在 `library_identity_history` |
| `project_targets` | 一个项目关注一个机构 / project_target_id | 批次、搜索语义、直接控股上级与完整路径、项目级扫描覆盖、独立增量游标 |
| `target_relationships` | 一条有方向且有证据的机构关系 | 主管、控股等关系；保留项目场景，不将间接持股当直接持股 |
| `tasks` + `mobile_collect_checkpoints` | 一次任务及固定范围的检查点 | 任务执行/终态、来源阶段、扫描时间、增量窗口；排队不计实际扫描完成 |
| `source_documents` | 一个规范 URL / document_id | 全局来源身份，按 distinct document_id 统计篇数 |
| `source_document_versions` | 一份稳定正文 / version_id | 不可变内容、归档时间、证据引用；变化数为每文档 ready 版本数减一，不计重采、分析重试或失败占位 |
| `source_document_links` | 来源在 Project/Target 中的发现场景 | 场景归属、相关性、搜索词、任务与发现时间，不能解释成文章全局事实 |
| `findings` | 来源事实及累计 evidence | 联系方式查询复用 group_key 逻辑读模型；统计联系人/电话时不能把证据条数当去重人数 |
| `persons` | 一个明确虚构的人物 / person_id | 当前完整档案与人设版本、行业分类；不能作为真实雇佣或联系方式证据 |
| `person_profile_versions` | person_id + profile_version | 不可变人物历史快照；保留每次更新前后状态并支持重启恢复 |
| `industry_organization_facts` | 行业 + Target + 来源版本 / fact_id | 真实公司/机构与公开办公联系方式、邻近原文、归档身份、核验时间 |
| `persona_coverage_jobs` | 一个行业大类 / job_id | 覆盖目标、阶段、租约、重试、缺口、已生成 person_ids 与 fact_ids |

事实表关联优先使用稳定 ID，名称只用于解析与展示。来源统计跨项目 distinct document_id，任务统计 distinct task_id，机构统计通过 canonical_target_id 去重；行业机构数可在多个行业同时出现，跨行业总数要再次按 Target 去重。版本变化是已保存内容的变化，不能证明网站所有历史修改均被捕获。增量成功边界必须按 ProjectTarget + scope_key 分组，不能拿最大值宣称所有范围都已覆盖。

身份投影缓存最多 30 秒，显式刷新可立即重算，原始内容与归档版本不复制。新增 Target 自动进入下一次全库索引；不同归属、祖先与后代、仅共享简称的机构禁止自动归并。API 的 `member_target_ids` 保留旧身份，便于分析侧进行可审计的关联。

## 人设行业自动补齐

目录来自[国家统计局国民经济行业分类](https://www.stats.gov.cn/sj/tjbz/gmjjhyfl/)，使用 GB/T 4754—2017 按第 1 号修改单修订的 20 门类、97 大类。随代码保存 `industry_catalog.json`、原始文件 URL、SHA-256 与获取日期；不保存手工编造的公司或人设样本。

`api.services.persona_coverage` 负责覆盖规划；后台 runtime 默认不执行外网工作，用户发起后通过统一配置 `persona_coverage.enabled` 启用。每个行业默认要求 4 条完整、自洽的虚构人设。默认 `generation_mode=context`，经 `api.services.persona_generation` registry 分派到独立上下文生成服务，模型自动规划差异化岗位并并发补齐档案；来源数量、真实机构与电话证据不作为入库或覆盖前提。`researched` 为可选来源研究模式，继续复用已有研究与归档能力。

两个 worker 经 DAO 原子认领、续期、幂等落库与检查点恢复，跨行业采用广度优先，不串行堵塞主 API。单轮失败最多 3 次退避尝试，之后保留缺口并在次日自动补齐；不要求用户补填缺失内容。手机采集仍使用原设备队列，该 worker 不接触 ADB 或手机租约。

可选研究模式的机构事实由现有 Chrome Provider 获取公开页面，经结构化模型提取，再复用 SourceDocument 服务归档，并与固定版本正文逐字核验机构名和邻近上下文。办公电话仅接受公开总机、热线或固定电话，个人手机号不写入虚构人设。真实参考资料未取得时保持其事实字段为空，不影响默认模式生成完整虚构上下文。虚构公司业务、地址、网站、办公电话、邮箱、微信和联络流程保存在 `persons.company_*` 与 `scenario_contact`，标注 `information_origin=fictional_context`；参考资料与演练设定分层，不能把生成内容当作真实机构或实际雇佣证据。模型没有访问过的来源不会作为证据写入。

人设写入通过原子快照 outbox 保存前后版本，再投影到 `person_profile_versions`。后台中断可从 outbox 恢复；旧档案只保存现存版本，不补造已丢失的历史快照。行业分类由明确的行业任务绑定，已有行业与目录大类全称精确一致的自动分类；仅标注大门类的旧人设保留原资料，不猜测细分行业。

## 验收

- 全部历史项目、子单位和孙单位可被搜索；同一单位跨项目合并，项目关联可追溯。
- 名称相同但上级不同、父子共享别名、循环关系及历史停用关系具有明确行为。
- 资料、扫描历史、增量边界和版本变化可以从库条目打开；招投标继续应用统一主体归属审核。
- 分页与筛选使用服务端读模型；实际数据库查询和浏览器桌面/窄屏均需验证。

新上下文调用沿用统一模型、Prompt 库和 token 观测，最多 4 个并发模型请求；生成后独立审校毕业、工作和家庭时间线，`context_review` 保留审校与修订记录，完整字段和逻辑检查失败时有界修订。已有尚未审校的上下文优先原身份升级，不重新造人。人物真实联系方式字段仍为空，模拟联络方式只在明确标注的 `scenario_contact` 中保存，持续完善保留稳定人物身份与旧来源。

`context_review.policy_version=2` 同时要求明确从业年份、工作年限和子女出生/年龄的算术检查通过；模型修订只补上下文，不以来源真实度设门槛。纯上下文生成的 `research_rounds` 为 0；旧启动默认值误计为研究的记录，按仅有 `synthetic_context` 的生成记录修正，并保存新的档案版本。覆盖报表 `policy_version=3` 标明当前计数口径。
